EDK nominal evidence and spec-evidence source is intentionally written to
the SPEC target, even where the current frontend cannot check it yet.

Target model:

```etas
type WorkspaceRoot;
type ReportsRoot;

spec WorkspaceRegion;
impl WorkspaceRoot ~ WorkspaceRegion;
impl ReportsRoot ~ WorkspaceRegion;

type WorkspacePath<R ~ WorkspaceRegion> = {
    value: string,
};

spec ReadablePath<R ~ WorkspaceRegion>;
spec WritablePath<R ~ WorkspaceRegion>;
spec ListablePath<R ~ WorkspaceRegion>;
```

EDK package APIs should use checked constructors to produce evidence values and
spec constraints to consume them. For example, `report_path(value)` validates
and normalizes a runtime string before returning `WorkspacePath<ReportsRoot>`,
and write APIs can require `WritablePath<ReportsRoot>`.

Current frontend/package-manager blockers observed while wiring EDK to this
target:

- generic ordinary flows, source-bodied tools, and effect actions with
  parameterized spec bounds such as `P ~ WritablePath<ReportsRoot>` are not
  accepted/solved reliably by the current frontend; observed diagnostics include
  `syntax::MissingToken: expected parameter list` at `public tool name<T ~
  SpecEvidence>(...)` and `action name<T ~ SpecEvidence>(...)` declarations;
- primitive-backed applied nominal accessors are not used for workspace paths;
  `WorkspacePath<R>` is record-backed and `path_value(path) -> string` reads the
  validated `value` field. Downstream package metadata still cannot emit the
  applied nominal `WorkspacePath<WorkspaceRoot>` schema when other packages
  depend on `edk-workspace`;
- nominal record wrappers such as `HttpUrl`, `PublicHttpUrl`, `HeaderName`, and
  `HeaderValue` need explicit constructor/accessor support for package-internal
  validation, preflight, wire lowering, and mock matching; current checking
  reports field access and record-constructor mismatches once these are nominal;
- runtime action payload policy needs a source-level implementation path:
  `EdkHttp.request` is now written as
  `action request(request: HttpActionRequest) -> HttpActionResponse`, and
  method/host must remain payload fields. EDK must not
  restore runtime method/host values in `<...>` or the old
  `request(method, host, request)` signature to keep exact policy summaries
  green. The minimal `custom_action_scope_gap` fixture must reject
  `perform EdkProbe.request<request.host>(request)`;
- bodyless or hidden-representation handles need a package-visible trusted
  construction path for runtime adapters, while remaining unforgeable from
  production package roots; `edk.browser.types.BrowserSessionRef` is now written
  as a bodyless nominal handle, production `create_session` / `attach_session`
  produce it via `EdkBrowser.create` / `EdkBrowser.attach`, and
  `edk.browser.mocks.mock_session` now produces a separate
  `MockBrowserSessionRef` through `EdkBrowserMock.session` rather than a
  production `BrowserSessionRef`;
- Browser page actions and tool wrappers are now written against spec evidence:
  `navigate/read` and `open_page/read_page` consume `BrowserSession`;
  `click` and `click_selector` consume both `BrowserSession` and
  `ParsedSelector`; and `screenshot_request` is modeled as
  `ScreenshotRequest<S ~ BrowserSession>`. Current frontend checking cannot yet
  solve concrete `BrowserSessionRef -> S ~ BrowserSession` or
  `Selector -> P ~ ParsedSelector` calls reliably, even when the impl appears in
  the same source graph.
- Browser selectors no longer use `SelectorParseResult` with an invalid fallback
  `Selector`; checked constructors now return `Result<Selector, SelectorError>`
  and failure stays in `Err`.
- Browser selectors now separate representation from parsed evidence:
  `SelectorSpec` is the raw shape, `Selector` is checked parsed evidence, and
  only `Selector` implements `ParsedSelector`.
- Browser URLs now separate representation from navigation-target evidence:
  `UrlSpec` is the raw shape, `Url` is checked evidence, and `url(...)` /
  `https(...)` return `Result<Url, BrowserError>` after validating scheme,
  host, and path.
- Email and GitHub package smokes/fixtures no longer manufacture invalid
  fallback evidence values such as empty `EmailAddress`, `SmtpEndpoint`,
  `GitHubRepoRef`, `PullRequestRef`, `ReviewComment`, or `GitHubQuery` in
  `must_*` helpers; checked constructor failure now propagates as typed
  `Error<...>` in those test surfaces.
- Email addresses, accounts, provider endpoints, and headers now separate raw
  representation from evidence: `EmailAddressSpec`, `EmailAccountSpec`,
  `ProviderEndpointSpec`, and `EmailHeaderSpec<N>` are raw shapes;
  `EmailAddress`, `EmailAccount`, `ProviderEndpoint`, and
  `EmailHeader<N ~ UserSettableEmailHeader>` are checked evidence values.
  `UserEmailHeader` is the production draft/header storage alias, and
  `EmailHeaderName` / `EmailHeaderValue` are checked evidence values.
  `parse_header(...)` is the checked string boundary,
  `header<N ~ UserSettableEmailHeader>(...)` is evidence-only, and managed
  headers such as `Subject` are rejected instead of being smuggled through a
  fake `empty_header` fallback. Public value accessors use
  `email_header_name_value(...)` / `email_header_value_text(...)`; raw helper
  names are private implementation details.
- Email drafts are now parameterized by deliverable-address evidence:
  `EmailDraft<A ~ DeliverableAddress>` carries the recipient evidence type
  through `to`, `cc`, and `bcc`; `draft`, `draft_to_one`, `with_cc`,
  `with_bcc`, MIME helpers, receipts, and `send` preserve `A` rather than
  accepting an unqualified draft surface.
- Email SMTP endpoints now separate raw endpoint shape from TLS-required
  evidence: `SmtpEndpoint` is the representation, `TlsSmtpEndpoint` is the
  checked evidence type, and only `TlsSmtpEndpoint` implements
  `TlsRequiredEndpoint`.
- `GitHubTokenRef` is now written as `SecretKey<GitHubToken>` rather than a
  string wrapper, and token-ref helpers fail closed until source-level
  `SecretKey<K>` / `SecretValue<K>` construction/import metadata is available;
  package smoke and the pure surface fixture assert both this fail-closed path
  and malformed token reference input rejection;
- `BranchRef` is now a nominal GitHub evidence type produced by
  `branch_ref(value) -> Result<BranchRef, GitHubError>`; `pull_request(...)`
  consumes `BranchRef` for `head` and `base` instead of raw strings;
- `BranchRef` now separates raw representation from evidence:
  `BranchSpec` is the raw shape, `BranchRef` is checked evidence, and only
  `BranchRef` implements `GitHubBranchRef`;
- `PullRequestRef<R, H, B>` now separates raw representation from evidence:
  `PullRequestSpec<R, H, B>` is the raw shape, `PullRequestRef<R, H, B>` is
  checked PR evidence, and only checked PR evidence implements the
  pull-request target spec;
- `GitHubRepoRef` now separates raw representation from evidence:
  `GitHubRepoSpec` is the raw shape, `GitHubRepoRef` is checked repository
  evidence, and only `GitHubRepoRef` implements `GitHubTarget`;
- `GitHubRestPath` and `ReviewPath` now separate raw representation from
  evidence: `GitHubRestPathSpec` / `ReviewPathSpec` are raw shapes, while
  `GitHubRestPath` / `ReviewPath` are checked path evidence produced by
  constructors; `query(...)`, `RestRequestSpec.path`, and
  `review_comment(...)` no longer consume raw path strings;
- `ReviewComment<P>` now separates raw representation from evidence:
  `ReviewCommentSpec<P>` is the raw shape, and checked `ReviewComment<P>`
  evidence is produced by `review_comment(...)` after line/body validation;
- Git repository values now follow the same evidence pattern:
  `GitRepoSpec`, `BranchSpec`, `RemoteSpec`, and `GitStatusEntrySpec` are raw
  shapes; `GitRepoRef`, `BranchRef`, `RemoteRef`, and `GitStatusEntry` are
  checked evidence values produced by `git_repo(...)`, `branch(...)`,
  `remote(...)`, and `status_entry(...)` returning `Result<...>`; invalid
  repo paths, branch names, remote URLs, and status paths stay in `Err` instead
  of manufacturing bad evidence for later validation;
- the old `empty_rest_path()` public helper has been removed so
  `GitHubRestPath` evidence is produced through `rest_path(...)` even for the
  empty PR-query path case;
- HTTP method and URL constructors now use evidence values: `HttpMethod` is a
  nominal method evidence type produced by checked `http_method(...)` or fixed
  constructors such as `get_method()` / `post_method()`, public URL
  constructors (`https`, `http`, `url_with_port`) return
  `Result<PublicHttpUrl, HttpError>`, and configured request builders consume
  `HttpMethod` plus `PublicHttpUrl` instead of raw `string` / `Url`;
- HTTP no longer exposes the old `edk.http.headers.normalize.header` raw
  `HeaderName` / `HeaderValue` helper. Request headers now separate raw shape
  from evidence: `HeaderSpec<N>` is the raw shape, `HeaderEvidence<N>` is the
  evidence value, and public construction flows through checked
  `user_header_name(...)`, `header_value(...)`, and `header(...)`;
- HTTP request headers are modeled as `HeaderEvidence<UserHeaderName>` through
  the `Header` alias, while response/wire headers use separate `WireHeader` /
  `ResponseHeaders` evidence. External source must not be able to construct
  request headers from raw `HeaderSpec`, ordinary `HeaderName` evidence, or
  managed header names;
- package metadata still needs to carry these nominal/spec facts, effect
  summary types, and custom action static families without degrading them to
  unscoped strings or mismatching `EdkHttp.request` with a different action
  declaration.
- `etas pkg lock` for the new email account/provider negative fixtures is
  currently blocked before intended diagnostics because `edk_email` depends on
  `edk_http`, and `edk_http` cannot yet produce checked package metadata for
  its nominal method/URL/header evidence source.
- `etas pkg lock` for the new HTTP method negative fixtures is currently
  blocked before intended diagnostics for the same `edk_http` package metadata
  reason; the fixtures express the target boundary but are not yet verified to
  the target diagnostic.

- parse and type-check applied nominal record constructors such as
  `WorkspacePath<ReportsRoot> { value = value }`, `PullRequestRef<R, H, B> { ... }`,
  `GitHubQuery<P> { ... }`, and `RestRequestSpec<GitHubRestPath> { ... }`;

  representation for model-callable wrappers over spec-constrained flow APIs;
- support explicit construction/destruction APIs for representation-backed
  nominal types, including applied nominal types;

  evidence such as `EmailHeader<N ~ UserSettableEmailHeader>` and
  `EmailDraft<A ~ DeliverableAddress>`, plus HTTP request/response header
  raw/evidence pairs such as `HeaderSpec<UserHeaderName>` /
  `HeaderEvidence<UserHeaderName>` and `HeaderSpec<WireHeaderName>` /

  opaque/bodyless handle materialization path for mocks and runtime adapters;
